# 对局记录只存摘要

**结论**：每局结束在 localStorage 记一条**摘要**（时间 / 维数 / 尺寸 / 选项 / 对手档位 / 我执色 / 结果 / 落子数 / 转动数），键 `gomoku.records.v1`，上限 50 条；入口是右上角第三颗键「记录」（浮层列表 + 两段确认清空）；**这不是"存档"** —— 读它回不到那盘棋。

**为什么只存摘要**：摘要一条几十字节；棋谱（逐步回放）要另做一个回放视图，是下一版的事。README「已知限制」那句"没有存档"说的是"中途关掉页面回不到对局"，被否掉的是**存档**，不是记录。

**语义（容易写错的两处）**：
- **悔棋撤记录**：终局后悔棋救回这一局 → 刚记的那条同步撤掉（"这局还没结束"）；所以记账存的是 recId 不是"列表最新一条"。重开（`R`）**不撤** —— 那一局确实下完了。重开与悔棋的分叉就在 `onReset`（只忘 recId）与 `onMoveUndone/onRotationUndone`（真删）。
- **单一同步点**：记账与撤账都从 `syncWinBanner` 这条线走 —— 落子 / 转动 / 时间翻转四条终局路径都汇到它；各写一份的后果是"某种赢法不记"（和横幅当年踩过的坑同构）。

**入口为什么在右上角**：起始界面加一行顶破"六语 1280×800 不滚动"的硬不变量（见 [[坑/起始界面高度预算极紧]]）；游戏面板那一行手机横向本来就紧。新键排最右（不是最左）是保 `#langList` 的 `left:0` 锚第一个孩子（语言键）——插到最前会让语言列表对着别的键展开。与规则浮层**互斥**（开一个关另一个）：省掉层级与 Esc 次序两套各自为政的逻辑。

**代价与边界**：进 localStorage 的从"只有语言"变成两项（代码里两处注释同步改了）。存储是用户可改的 —— 坏了当空列表（不主动删，下次写入覆盖），渲染走 `escapeHtml`，档位下标读出界要夹回。

**证据**：`dom-smoke` 12 步（字段 / 悔棋撤回 / 教学不记 / 50 条裁剪 / 坏数据 / 访问抛异常降级 / 面板互斥与 Esc / 清空两段确认 / 切语言重渲染 / 四维转动数）；`browser-check` 6c 节（真浏览器一条龙 + 第三颗键的几何 + 截图 `15-对局记录.png`，时间戳在拍照前钉死）。
