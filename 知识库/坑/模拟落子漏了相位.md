# 模拟落子漏了相位

**结论**：AI 搜索里**读**棋盘走的是带相位的 `aiTag`（`cellOf` 编码），而**模拟落子**原来写的是朴素色值（`board.set(..., mover)`），`judge` 也没传 matchValue —— 于是四维模式下轮到**永夜**（相位 1）时，搜索里模拟出来的黑子（值 1）对不上"黑·夜"（值 5）：评估看不见自己的进攻，`judge` 还按朴素值把已休眠的黎明线当活线。

**症状（2026-10-14 实测复现）**：

- **幻影胜手**：黎明四条黑子 + 会话在永夜，`aiSearchMove` 对补第五颗的位置报 **v = 1e9**（= 搜索的"胜"常量），`aiChooseMove` 选它 —— 真落下去 `Placed`，什么都没赢。
- **漏胜**：两条三连交叉（一手双四的强制胜），黎明下 ultra 给胜着，同一局面放永夜去下别处；VCF/VCT 整条链在夜里断掉。
- 相位 = 0（三维、黎明）时两套编码恰好相等 → **所有既有测试全绿**，白天怎么下都是对的 —— 这正是它藏得住的原因。

**为什么**（写侧漏了）：`aiPhase` 只被接进了"读"的一侧（`aiThreatAt` 的 player 参数换成 `aiTag`），五个模拟落子点（`aiNegamax`、`aiSearchMove` 根节点与兜底、`aiVcf`、`aiVctAfter`）仍写朴素色值。判胜的 `judge` 也必须传 `matchValue = cellOf(last.p, aiPhase)`，否则按朴素值把黎明线当活线。

**修法与边界**：

- 模拟落子一律 `cellOf(colour, aiPhase)`；`judge` 传同样的值。相位 = 0 时逐字节等价，三维与黎明完全不受影响。
- 搜索**不模拟**"落子推进相位、线可能翻转"（一条搜索线内相位恒定）—— 刻意的简化，写在 `aiPhase` 的注释里。
- 同类物：转动路径靠 `RotateOutcome.lineLengths` 带出线长（见 [[坑/转出线不等于赢]]）—— AI 段有"全盘扫描只许出现在转动判定里"的源码级红线，别在 AI 段自己补扫。

**证据**：`ai.test.mjs` 13d 组（幻影 v < 1e8 + 昼/夜对称 + 强制胜走完）。修复前的红：`v=1000000000`；黎明 (5,1,5) / 永夜 (5,6,5)。**晨昏机制此前几乎没有断言**（只有 4.4 回滚与悔棋时钟两条）——这块空白见 [[待办/晨昏的两笔欠账]]。
