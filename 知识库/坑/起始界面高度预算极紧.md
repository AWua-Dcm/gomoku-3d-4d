# 起始界面高度预算极紧

**症状**：往起始界面加一行、或把主标题放大一档，某种语言的「开始游戏」就被挤出 800px 高的视口。

**原因**：硬不变量是"**六种语言在 1280×800 下，「开始游戏」都不用滚动就能看见**"，而约束边界永远是**法语**（规则摘要定高 + 按钮文案最长）。法语内容高约 800px、**与视口无关**——1280×800 只剩 2px 余量；1366×768 从 v3.1.5 起一直是超的。只看中文会得出"还有很多地方"的错误结论。

**规矩**：动起始界面前先跑 `_verify/browser-check.mjs` 里那条断言——它会打印六种语言的 `startBtn.bottom / contentH`。高度上有两处**不能碰**：`#setup` 的 `gap` 与 `--cool3d-take`（外部依赖：`#extraRow` 高度、紧凑档行距，都挂着"三维↔四维逐像素一致"的断言）。要收高度，优先收**内边距和行高**。已经用掉的杠杆（别再找一遍）：内边距已归零、标题三行行高已到 0.9 左右、`--summary-h` 已收到 84（行高必须同步 1.3，两个数决定一件事）。

**出处**：v3.1.6 期间连续四轮实测（2026-10-05/06，每轮都超、每轮从别处还回来）；browser-check 的对应断言。
