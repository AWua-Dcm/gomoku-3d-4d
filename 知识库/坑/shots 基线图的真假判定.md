# shots 基线图的真假判定

**症状**：跑完 `bash _verify/run-all.sh`，`_verify/shots/` 里必然有一批图显示 M。**哪些是环境噪声、哪些是真改动，不能按图号一刀切。**

**原因**：第 8 步（browser-check）会在报告失败**之前**重拍那批基线图——有时候拍的是故意弄坏的页面之外的正常渲染，但渲染本身随环境（Chrome 版本、机器）有差异。

**规矩**：对拍要拿 HEAD 的干净副本——`git worktree add` 或 `git show HEAD:path` 取出来、**渲染到别处，基线目录一个字节都不碰**——然后逐张比三份 md5（已提交 / HEAD 副本 / 工作区）：和 HEAD 副本一致的那张，说明工作区**真改了**；对不上的，说明这个图号在本机本来就复现不了（纯噪声）；工作区与 HEAD 副本一致则说明"没碰它"。**这张表随环境漂移，上一轮的结论不能用在下一轮**。补充：噪声按"像素差 + 包围盒"判，别看 md5 单数（12.8 万 px 的差照样可能是噪声）；**同一份代码连跑两遍**比 HEAD 对拍更硬——v3.1.7 用的就是这招。两个机关：①端口 9401 要是被上一轮没关掉的 headless 占着，检查会连到旧浏览器上、报一批与改动无关的假红——它现在开头就自检，占着就以退出码 2 结束并给出提示；②会临时改坏 index.html 的那两个注入脚本已经改成把截图写去临时目录——**故意弄坏的页面绝不能拍进版本库**，否则 `git status` 从此分不清"图被弄脏"和"界面真的改了"。

**出处**：`_verify/run-all.sh` 文件头；2026-09-25 / 09-26 / 10-01 三次实测记录。
