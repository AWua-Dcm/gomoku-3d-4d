# shots 基线图的真假判定

**症状**：跑完 `bash _verify/run-all.sh`，`_verify/shots/` 里必然有一批图显示 M。**哪些是环境噪声、哪些是真改动，不能按图号一刀切。**

**原因**：第 8 步（browser-check）会在报告失败**之前**重拍那批基线图——有时候拍的是故意弄坏的页面之外的正常渲染，但渲染本身随环境（Chrome 版本、机器）有差异。

**规矩**：拿 HEAD 干净副本在本机渲染同一张来对拍——`git worktree add` 或 `git show HEAD:path`，**写到别处、别碰基线目录**——比三份 md5（已提交 / HEAD 副本 / 工作区）逐张判：已提交 == HEAD 副本 → 工作区那张是**真改动**；已提交 != HEAD 副本 → 那个图号在当前环境下本来就不可复现（噪声）；工作区 == HEAD 副本 → 这次改动没碰它。**这张表随环境变，别沿用上一轮的结论**。补充判据：噪声要按"像素差 + 包围盒"判、别只看 md5（一次 12.8 万 px 的差也可能是噪声）；**同一份代码连跑两遍**比拿 HEAD 对拍更硬（v3.1.7 用的就是这个）。另两个机关：端口 9401 被上次留下的 headless 占着会连到旧浏览器、报一堆与改动无关的假红（browser-check 现在开头自检、退出码 2 并提示）；`inject-*.py` 会临时改坏 index.html，它们已改成写临时目录——**别让故意弄坏的页面拍进版本库**，否则 `git status` 从此分不清"图被弄脏"和"界面真的改了"。

**出处**：`_verify/run-all.sh` 文件头；2026-09-25 / 09-26 / 10-01 三次实测记录。
