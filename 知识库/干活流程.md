# 干活流程

**一句话**：在这个仓库里改东西的固定路线——从动手到线上。[[首页]] 管"为什么"，这页管"按什么顺序"；内容是路线图，每步的正文都在链到的笔记里，不在这里抄。

## 1. 开工前

先读 [[首页]]。要动的那块，把对应的 决策/ 与 坑/ 翻一遍——踩过的坑基本都写下来了。

## 2. 改（"改 X 必连改 Y"）

| 改什么 | 必须连着改什么 |
|---|---|
| `RULES_SPEC*.md` | 重嵌进 index.html：`node _verify/embed-rules.mjs`。见 [[决策/规则全文是生成的]] |
| 标题 / 水印文案 | 书法字体子集重切——不在子集里的字会**静默**变豆腐块。见 [[决策/单文件里塞书法字体]] |
| 规则内核 | 不许动冻结向量；新规则在 `rules.test.mjs` 里**明确加**断言。见 [[坑/冻结向量不能改]] |

中文 / 外语文案的口径见 [[决策/中文原文留在 HTML]]。

## 3. 验

- 一条命令：`bash _verify/run-all.sh`——八步全绿；每步查什么见 [[验证/九步与断言地图]]（项数以 run-all 输出为准）。
- 第 8 步截图在 `_verify/shots/`：对拍先钉住会动的东西（[[坑/截图对拍先钉住会动的东西]]），图的真假怎么判（[[坑/shots 基线图的真假判定]]）。
- 这些绿为什么算数：[[验证/证据的分级]]；检查本身也被负向验过（[[验证/注入验证]]、[[验证/假测试的两起案例]]）。

## 4. 沉淀

有"为什么"才写：新决策进 决策/、新坑进 坑/、验证方法变了进 验证/——现有文档已写清的只链接不抄写。改完跑 `node _verify/kb-links.mjs`，悬空 / 歧义 / 锚点 / 孤儿全 0 才算过。

## 5. 发布

推送必须走本地代理（`-c` 写在子命令之前；代理可能没开着，别去改全局配置）——查序与线上验证见 [[坑/推送 GitHub 与 Pages 验证]]。线上发布物就是仓库里那份 `index.html`（`pages.yml` 只拷它上台）。

## 6. 兜底人验

机器验不了的（配色、手感、棋力……）进 [[打开流程]] §A 验收清单与"还没验证过的部分"。
