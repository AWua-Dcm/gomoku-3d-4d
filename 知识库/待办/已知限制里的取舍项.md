# 已知限制里的取舍项

**结论**：这几条是"量到过、决定不修"的排版 / 设计取舍——不是没发现的 bug，是**修它要付出的代价大于收益**。改之前先看"为什么留着"。

1. **窄窗口 + 长游戏名时主标题与右上角两个固定键重叠**（900×700 上六种语言全中）。主标题只按视口宽封顶、没给那两个键让位；按"缩到不重叠"算，900 宽下字号要掉到 ~40px——那是排版上的一次取舍。
2. **四维摘要框在 en / fr / ru 下裁掉最后一行**。那个框是定高（英文 88px / 其余 84px），而这三段四维说明在 640px 宽里要折 6~7 行（实测 123px）。改成"按内容长高"会**当场踩断言**：「切三维↔四维时按钮一个像素都不动」（实测会动 4~34px）。框里会出现内部滚动条，滚一下还是看得见。
3. **三维 + 魔方旋转 + 人机 + 非默认尺寸（≤9 / ≥25）时摘要到三行**，那块 44px 只装两行——「人机对战：你执黑…」要滚一下才看得全（4D 和普通三维里装得下）。要改就得按内容自适应高度（下面几行会动 19px）。

**共同的"为什么留着"**：都属于排版决策——要真修得**砍文案**或**从别处还高度**（起始界面的高度预算极紧，见 [[坑/起始界面高度预算极紧]]），不是纯 bug 修得掉的。
