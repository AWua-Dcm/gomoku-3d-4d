# v2.10.15 四维人机强化 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把四维人机的转动判断从「档位启发式抢跑」改成「和落子同台竞价」，并给极限档加上威胁空间搜索（VCT）、Zobrist 置换表和无损的走法生成优化，使新人机对旧人机的配对胜率达到 70% 以上。

**Architecture:** 全部改动都在 `Web_Gomoku3D/index.html` 的内核区间 `GOMOKU-CORE-BEGIN/END` 内（约 4196-5215 行），加一个 `_verify/` 下的离线测量脚本。搜索主干（α-β 负极大）不动，只做三件事：把每个节点的威胁评估改成无损的「条带」写法、加一层置换表、把转动从根节点的独立分支挪进和落子同一个候选池。

**Tech Stack:** 纯 JS（ES2020 语法，无模块、无依赖）、Node 24 内置模块、零 npm 依赖。测试是自制的 `check()` 断言（不是框架），用 `node <file>` 直接跑。

**Spec:** `docs/superpowers/specs/2026-09-29-4d-ai-v2.10.15-design.md`

## Global Constraints

- **零依赖**：不许 `npm install`，不许引任何包。只能用 `node:` 内置模块。见 `.gitignore` 文件头。
- **单文件**：游戏本体只有 `Web_Gomoku3D/index.html` 一个文件（583KB，9896 行）。内核代码必须留在 `/* GOMOKU-CORE-BEGIN */` 与 `/* GOMOKU-CORE-END */` 之间，因为测试是从标记之间**抽出来单独求值**的。
- **内核区间里一个字的中文注释都可以有，但不许出现界面文案**；文案走 `TEXT` / `STATIC_TEXT` + `say()`。
- **确定性**：同局面 + 同种子 + 同配置 → 同一动作。全项目唯一随机源是 `aiRng(seed)`（[index.html:4330](../../Web_Gomoku3D/index.html#L4330)）。**任何地方都不许出现 `Math.random` 或 `Date.now()` 参与决策。**
- **深度一律奇数**（`tests/ai.test.mjs:433` 有断言）。
- **绝不出抛**：`aiChooseMove` 任何守卫不成立都返回 `{kind:"none"}`；页面控制台不许有任何输出（browser-check 硬断言）。
- **文案六语言**：中文在 HTML / 调用点，英文日在韩俄法进 `TEXT` 表（[index.html:5490](../../Web_Gomoku3D/index.html#L5490) 起）。键必须是**字面量**。
- **版本号**：本次 `v2.10.15`。
- **每完成一个 Task 单独提交**，实测数字写进 commit message（这个仓库的既有做法，见 `git log`）。

## Review Focus

这些是规格没有明说、但最可能真的把人绊倒的输入/情形。每条都在下面某个 Task 里有对应测试：

1. **棋盘尺寸正好卡在新边界上**（8 和 30），以及三维的长方体（如 `8 × 30 × 30`）——Zobrist 表的按尺寸惰性分配、`AI_SEARCH_DROP` 的候选数阈值都在这里最容易算错。
2. **`winLength` 不是 5** 时条带缓冲会不会越界。现在 `RuleSet` 把它写死成 5 且全项目没有第二处赋值，但条带是定长数组，越界写会静默污染相邻内存。要显式守卫。
3. **转动冷却设成 0 或 1**（每手都能转）时，根节点转动探针的代价会不会失控——极限档要全枚举 3×N×3 个转动，8³ 是 72 个，每个都要跑一遍搜索。
4. **密盘**（30³ 塞几千颗子）下置换表槽位被冲垮、候选数触顶 `AI_CANDIDATE_CAP`，此时预算计数器还兜不兜得住。
5. **悔棋 / 重开之后**重复用同一个 session 出招——置换表与 Zobrist 基准值必须跟着重置，否则会读到上一局的残影。

```js
//
// 【为什么必须是"配对"，不能是"两色各半"】这个工程已经踩过一次：
// 两边内核**完全相同**的对照组照样打出 53 / 55 / 53 / 60% —— 第一方被系统性照顾。
// 原因是颜色和开局手数各排各的周期，混在一起了。现在第 2k 局与第 2k+1 局
// **共享同一个开局种子、只对调颜色**，于是对照组恒等于 50.0%。
// 对照组的分数不是恰好 50.0% 就说明测量台坏了，这时**不许报胜率**。
// （这套方法论见 Web_Gomoku3D/tests/ai.test.mjs 的 selfPlay 那一节。）
//
// 【为什么旧版从 git 取】"新旧对拍"要的是两份真的内核，不是同一份代码换个参数。
// --old 可以给 git revision（如 4337e18），脚本用 git show 取出那一版 index.html
// 再抽内核；也可以直接给一个文件路径。

// 用法：
//   node _verify/ai-ab.mjs --mode 4d --size 8 --cooldown 3 --games 40 \
//        --new HEAD --old 4337e18
//   node _verify/ai-ab.mjs --mode 3d --size 15 --games 40 --new HEAD --old 4337e18
//   # 测量台自检：新旧都给同一个 revision，得分率必须恰好 50.0%

function parseArgs(argv) {
  const o = { mode: "3d", size: 15, cooldown: 3, games: 40, new: "HEAD", old: "HEAD" };
  for (let i = 0; i < argv.length; i += 2) {
    const k = argv[i].replace(/^--/, "");
    const v = argv[i + 1];
    if (k === "mode") o.mode = v;
    else if (k === "size") o.size = parseInt(v, 10);
    else if (k === "cooldown") o.cooldown = parseInt(v, 10);

    else if (k === "old") o.old = v;
    else { console.error("未知参数 --" + k); process.exit(2); }
  }
  return o;
}

/** 取一份 index.html 的正文。参数是 git revision 或文件路径。 */
function readHtml(revOrPath) {

  return execFileSync("git", ["show", revOrPath + ":" + HTML_REL],

/** 从 index.html 抽内核区间并求值。和 tests/ai.test.mjs 用的是同一段标记。 */
function loadCore(html, label) {
  const s = html.indexOf("<script>");
  const e = html.lastIndexOf("</script>");
  if (s < 0 || e < 0) { console.error(label + "：找不到 <script> 块"); process.exit(2); }
  const full = html.slice(s + "<script>".length, e);
  const BEGIN = "/* GOMOKU-CORE-BEGIN */";
  const END = "/* GOMOKU-CORE-END */";
  const core = full.slice(full.indexOf(BEGIN) + BEGIN.length, full.indexOf(END));
  try {
    return new Function(core + `
      return { FourDSession, RuleSet, RotationMove, MoveStatus, EMPTY, BLACK, WHITE,
               opponentOf, aiChooseMove, aiRng };`)();
  } catch (err) {
    console.error(label + "：内核求值失败 —— " + err.message);
    process.exit(2);
  }
}

function mkSession(C, n, fourD, cooldown) {
  const rules = new C.RuleSet();
  rules.allowRotation = !!fourD;
  if (cooldown !== undefined) rules.rotationCooldownPlacements = cooldown;
  return C.FourDSession.create(n, BLK(C), rules);
}
// 黑先。这里写成一个函数只是为了让"谁先手"这件事在调用点看得见。
function BLK(C) { return C.BLACK; }

function applyAction(C, s, act) {
  if (act.kind === "place") return s.place(act.x, act.y, act.z);
  if (act.kind === "rotate") {
    return s.rotate(C.RotationMove.fromClockwiseTurns(act.axis, act.layer, act.turns));
  }
  return null;
}

/**
 * 一局。aIsBlack 决定 A 方执什么颜色。
 * **返回 {aScore, plies, rotations, endedBy}**，aScore ∈ {1, 0.5, 0}。
 */
function playOne(C, n, fourD, cooldown, lvA, lvB, aIsBlack, seed, maxPlies) {
  const s = mkSession(C, n, fourD, cooldown);
  const rng = C.aiRng(seed);
  // 随机开局：搜索是确定性的、不消耗随机数，固定开局下"N 局"其实是同一盘棋重复 N 次
  const open = seed % 7;                      // 0..6 手
  for (let j = 0; j < open && s.status === "Playing"; j++) {
    const em = [];
    const lo = Math.max(0, ((n / 2) | 0) - 3), hi = Math.min(n, ((n / 2) | 0) + 3);
    for (let z = lo; z < hi; z++) for (let y = lo; y < hi; y++) for (let x = lo; x < hi; x++) {
      if (s.board.isEmpty(x, y, z)) em.push([x, y, z]);
    }
    if (em.length === 0) break;
    const m = em[(rng() * em.length) | 0];
    s.place(m[0], m[1], m[2]);
  }
  let plies = 0, rotations = 0;
  while (s.status === "Playing" && plies < maxPlies) {
    const aToMove = (s.currentPlayer === C.BLACK) === aIsBlack;
    const lv = aToMove ? lvA : lvB;
    const act = C.aiChooseMove(s, { level: lv, seed: (rng() * 4294967296) >>> 0 });
    if (act.kind === "none") break;
    const r = applyAction(C, s, act);
    if (act.kind === "rotate") rotations++;
    if (!r || r.status === C.MoveStatus.Rejected || (act.kind === "rotate" && !r.accepted)) break;
    plies++;
  }
  const aWon = (s.winner === C.BLACK && aIsBlack) || (s.winner === C.WHITE && !aIsBlack);
  const aScore = s.winner === C.EMPTY ? 0.5 : (aWon ? 1 : 0);
  return { aScore, plies, rotations, status: s.status };
}

function duel(CA, CB, n, fourD, cooldown, games, seedBase, lvA, lvB, maxPlies) {
  let score = 0, wins = 0, losses = 0, draws = 0, plies = 0, rotations = 0;
  for (let i = 0; i < games; i++) {
    const aIsBlack = i % 2 === 0;
    // 配对：同 (i>>1) 的两局共享开局种子，只对调颜色
    const seed = seedBase + (i >> 1) * 7919;
    const r = playOne(CA, n, fourD, cooldown, lvA, lvB, aIsBlack, seed, maxPlies);
    // B 方视角重跑一遍太贵；A 方换色重跑即可，因为配对两局的种子相同
    score += r.aScore;
    plies += r.plies;
    rotations += r.rotations;
    if (r.aScore === 1) wins++; else if (r.aScore === 0) losses++; else draws++;
  }
  return { score, wins, losses, draws, games, avg: Math.round(plies / games), rotations };
}
```

```js
/**
 * 一条方向上的「条带」读数。**为什么要有它 —— 这是本段唯一一处纯性能改动。**
 *
 * 老写法对每个方向要扫 5 个窗口 × 5 格 = 25 次棋盘读取，13 个方向就是 325 次，
 * 而每个候选点要算两遍（攻方 + 守方）。条带把同一批格子**只读一次**：
 * 沿该方向从 -4 到 +4 读 9 格存进数组，之后 5 个窗口全在这个数组上滑，
 * 棋盘读取降到 13 × 9 = 117 次，**而且结果逐字段与老写法相同**（有对拍断言钉着）。
 *
 * 9 = 2 × (winLength - 1) + 1，winLength 恒为 5（RuleSet 的默认值，全项目没有第二处
 * 赋值它）。下面有守卫：真出现别的 winLength 就退回走老路，绝不越界写。
 *
 * 【模块级可变缓冲，和 AI_PT / aiSeenBits 同一类】aiThreatAt 不递归、不重入，
 * 调用方拿到的是六个计数（值类型），所以它不参与任何决策时序。
 */
const AI_STRIP_LEN = 9;
const AI_STRIP = new Uint8Array(AI_STRIP_LEN);
const S_EMPTY = 0, S_MINE = 1, S_OTHER = 2, S_OUT = 3;

function aiThreatAt(board, x, y, z, player, winLength, restricted) {
  // winLength ≠ 5 时条带装不下 —— 退回老写法。**这条守卫不能省**：
  // 条带是定长数组，不守卫就是静默越界写，会污染相邻的 TypedArray。
  if (winLength !== 5) return aiThreatAtSlow(board, x, y, z, player, winLength, restricted);

  let wins = 0, fours = 0, openFours = 0, threes = 0, twos = 0, over = 0;
  const nx = board.nx, ny = board.ny, nz = board.nz;
  const cells = board.cells;
  const sy = nx, sz = nx * ny;          // 扁平步长：index = x + sy*y + sz*z
  const half = winLength - 1;           // 4
  const strip = AI_STRIP;

  for (let i = 0; i < DIRS13.length; i++) {
    const d = DIRS13[i];
    const dx = d[0], dy = d[1], dz = d[2];
    // 读 9 格：偏移 -half..+half，第 half 位是本点自己
    let px = x - half * dx, py = y - half * dy, pz = z - half * dz;
    for (let k = 0; k < AI_STRIP_LEN; k++) {
      let v;
      if (px < 0 || py < 0 || pz < 0 || px >= nx || py >= ny || pz >= nz) {
        v = S_OUT;
      } else {
        const c = cells[px + sy * py + sz * pz];
        v = c === 0 ? S_EMPTY : (c === player ? S_MINE : S_OTHER);
      }
      strip[k] = v;
      px += dx; py += dy; pz += dz;
    }

    // 本点自己那一格一定是自己的子（调用方已保证），不用读
    strip[half] = S_MINE;

    let neg = 0;
    while (half - 1 - neg >= 0 && strip[half - 1 - neg] === S_MINE) neg++;
    let pos = 0;
    while (half + 1 + pos < AI_STRIP_LEN && strip[half + 1 + pos] === S_MINE) pos++;
    const run = 1 + neg + pos;
    if (run > winLength) { over++; continue; }

    const openA = (half - neg - 1) >= 0 && strip[half - neg - 1] === S_EMPTY;
    const openB = (half + pos + 1) < AI_STRIP_LEN && strip[half + pos + 1] === S_EMPTY;

    // 滑窗：窗口起点偏移 s，覆盖 strip 下标 half+s .. half+s+winLength-1
    // 由 s ≥ -(winLength-1) 得 half+s ≥ 0；由 s ≤ 0 得上界 2*half ≤ 8。刚好装满条带。
    let need = winLength;
    for (let s = -(winLength - 1); s <= 0 && need > 0; s++) {
      let ok = true, mine = 0;
      const base = half + s;
      for (let k = 0; k < winLength; k++) {
        const idx = base + k;
        if (idx === half) continue;              // 本点算自己那一颗
        const v = strip[idx];
        if (v === S_EMPTY) continue;
        if (v === S_MINE) { mine++; continue; }
        ok = false; break;                       // S_OTHER 或 S_OUT
      }
      if (!ok) continue;
      const gap = winLength - (mine + 1);
      if (gap < need) need = gap;
    }
    if (need === 0) wins++;
    else if (need === 1) { fours++; if (run === winLength - 1 && openA && openB) openFours++; }
    else if (need === 2) threes++;
    else if (need === 3) twos++;
  }
  return { wins: wins, fours: fours, openFours: openFours, threes: threes, twos: twos, over: over };
}
```

- [ ] **Step 1: 写置换表的核心（先不接进搜索）**

```js
/* --------------------------------------------------------------------------
   Zobrist 置换表。

   【为什么是 32 位整数而不是字符串/大整数】同局面同种子必须在任何机器上给出同一动作，
   所以键必须是确定的整数运算；字符串拼接慢得没法放进热循环，BigInt 更慢。

   【键里必须有的东西 —— 少一样都会读到脏表项】
     · 整盘每一格（Zobrist 主体）
     · 出子权 mover —— 同一个盘面轮到谁走，值完全不同
     · 双方受限身份 moverRes / foeRes —— 先手方长连判负、后手方 ≥5 即胜，规则不一样
     · tune 参数（winLength / branch）—— 本表【每手重置】，而一次 aiChooseMove 里
       tune 是固定的，所以不必进键；将来若要跨手复用，这里必须先补上。
   【冷却是怎么处理的】四维下 canRotate 由 placementsSinceLastRotation 决定，
   它【不在盘面上】。但转动不进搜索（转动只在根节点比价），搜索里棋盘只经 board.set 变化，
   所以搜索内部不需要冷却进键。根节点每次转动候选都重新算一次整盘哈希。

   【生命周期：代数戳，每手重置】和 aiSeenBits 同一套写法。这样确定性契约零风险 ——
   整个计算仍然是纯确定性的，也不会出现"跨手复用了不同参数下的表项"这种偶发脏读。
   -------------------------------------------------------------------------- */

const AI_TT_BITS = 16;
const AI_TT_SIZE = 1 << AI_TT_BITS;        // 65536 槽
const AI_TT_KEY = new Int32Array(AI_TT_SIZE);
const AI_TT_DEPTH = new Int8Array(AI_TT_SIZE);
const AI_TT_FLAG = new Uint8Array(AI_TT_SIZE);   // 0 空 / 1 精确 / 2 下界 / 3 上界
const AI_TT_VAL = new Float64Array(AI_TT_SIZE);
const AI_TT_MX = new Int16Array(AI_TT_SIZE);
const AI_TT_MY = new Int16Array(AI_TT_SIZE);
const AI_TT_MZ = new Int16Array(AI_TT_SIZE);
const AI_TT_GEN = new Int32Array(AI_TT_SIZE);
let aiTtGen = 0;
const TT_EXACT = 1, TT_LOWER = 2, TT_UPPER = 3;

/* Zobrist 随机表。按棋盘尺寸惰性分配：cellCount × 2 色 × 32 位。
   EMPTY 不占一项 —— 空就是 0，放子撤子用同一个值异或。 */
let aiZobColor = null;      // Int32Array(cellCount * 2)
let aiZobCells = -1;
const AI_ZOB_SEED = 0x5eed1234;
/** 出子权与受限身份的混合常量。取质数，和格子项独立。 */
const AI_ZOB_TURN = [0, 0x9e3779b1];            // 下标 = 颜色
const AI_ZOB_RES = [0, 0x85ebca6b, 0xc2b2ae35]; // 0 无 / 1 仅 mover 受限 / 2 仅 foe 受限 / 3 都受限

function aiZobristEnsure(board) {
  const n = board.cellCount;
  if (aiZobColor && aiZobCells === n) return;
  // 用内核自己的 PRNG，不许 Math.random —— 否则同局面在不同次运行里算出不同的表
  const rng = aiRng(AI_ZOB_SEED + n);
  const arr = new Int32Array(n * 2);
  for (let i = 0; i < arr.length; i++) arr[i] = (rng() * 4294967296) | 0;
  aiZobColor = arr;
  aiZobCells = n;
}

/** 整盘哈希。O(cellCount)，只在根节点调用（每手一次 + 每个转动候选一次）。 */
function aiZobristBoard(board) {
  aiZobristEnsure(board);
  const cells = board.cells;
  let h = 0;
  for (let i = 0; i < cells.length; i++) {
    const v = cells[i];
    if (v !== 0) h ^= aiZobColor[i * 2 + (v === BLACK ? 0 : 1)];
  }
  return h | 0;
}

/** 放子 / 撤子都用这一个：Zobrist 的异或是自己的逆运算，而 EMPTY 的项是 0。
    idx 是扁平下标，color 是 BLACK / WHITE。 */
function aiZobristMove(hash, color, idx) {
  return (hash ^ aiZobColor[idx * 2 + (color === BLACK ? 0 : 1)]) | 0;
}

/** 每手开头调一次。代数戳 +1 = 整表作废，不做逐项清零（65536 项的 fill 也是白花钱）。 */
function aiTtReset(seed) {
  aiTtGen = (aiTtGen + 1) | 0;
  if (aiTtGen === 0) { AI_TT_GEN.fill(0); aiTtGen = 1; }   // 绕回时清一次，别让旧代数变成 0
}

/** 槽位。**必须是无符号右移**：hash 是 32 位有符号，>> 会带来负数下标。 */
function aiTtSlot(key) { return key & (AI_TT_SIZE - 1); }

function aiTtProbe(key, depth) {
  const i = aiTtSlot(key);
  if (AI_TT_GEN[i] !== aiTtGen) return null;
  if (AI_TT_KEY[i] !== key) return null;      // 碰撞：键不逐位相同就当作没有
  if (AI_TT_DEPTH[i] < depth) return null;    // 存的那层比要的浅，不能用
  return { flag: AI_TT_FLAG[i], value: AI_TT_VAL[i],
           x: AI_TT_MX[i], y: AI_TT_MY[i], z: AI_TT_MZ[i] };
}

function aiTtStore(key, depth, flag, value, x, y, z) {
  const i = aiTtSlot(key);
  // 同槽已有本代更深的一项时让位 —— 浅的结果覆盖深的会让剪枝失效
  if (AI_TT_GEN[i] === aiTtGen && AI_TT_KEY[i] === key && AI_TT_DEPTH[i] > depth) return;
  AI_TT_GEN[i] = aiTtGen;
  AI_TT_KEY[i] = key;
  AI_TT_DEPTH[i] = depth;
  AI_TT_FLAG[i] = flag;
  AI_TT_VAL[i] = value;
  AI_TT_MX[i] = x; AI_TT_MY[i] = y; AI_TT_MZ[i] = z;
}
```

- [ ] **Step 1: 加 `DIRS26` 与 `aiCheapKey`**

紧挨着 `DIRS13_NEG`（`index.html:4321`）插入：

```js
/** 26 个邻居偏移。只给 aiCheapKey 用（它是排序的预筛，不参与任何判定）。 */
const DIRS26 = (() => {
  const out = [];
  for (let dz = -1; dz <= 1; dz++)
    for (let dy = -1; dy <= 1; dy++)
      for (let dx = -1; dx <= 1; dx++) {
        if (dx === 0 && dy === 0 && dz === 0) continue;
        out.push([dx, dy, dz]);
      }
  return out;
})();

/**
 * 预筛用的廉价键。**只用来决定"哪些候选值得算完整的 aiOrderKey"，不进分数。**
 *
 * 【为什么中心加权放在这里而不是评估里】aiCenterDist 的注释写着"只当 tie-break 用，
 * 绝不进分数"。这一条**不变**：中心加权是"同等威胁时先看中间"，不是"中间本身值分"。
 * 放进预筛键正好 —— 它本来就只在排序里起作用。
 *
 * 【为什么邻域子数能当预筛】搜索每个节点只展开 branch 个候选，却要为此把全部候选
 * （15³ 中盘约 235 个）都算一遍完整威胁。邻域子数和"这里能不能形成棋型"强相关，
 * 拿它取前 3×branch 再算完整的，能省掉九成开销。**代价是可能漏掉真正的好点**，
 * 所以根节点不筛（见 aiOrderTop 的注释），并且有对拍断言量化差异。
 */
function aiCheapKey(board, x, y, z) {
  let n = 0;
  for (let i = 0; i < DIRS26.length; i++) {
    const p = DIRS26[i];
    if (board.getOrDefault(x + p[0], y + p[1], z + p[2]) !== EMPTY) n++;
  }
  return n * 1000 - aiCenterDist(board, x, y, z);
}
```

- [ ] **Step 2: 加 `aiOrderTop`**

放在 `aiSearchCompare` 之后：

```js
/**
 * 候选排序。`preFilter` 为真时走两段式：先用 aiCheapKey 取前 3×k 个，再对这批算完整的
 * aiOrderKey 并按 aiSearchCompare 排。为假时全量算（老行为）。
 *
 * 【为什么根节点必须传 preFilter=false】根节点上"漏掉正确着法"的代价最大，
 * 而且它的开销一手只付一次。内层节点才筛。
 *
 * 【保留名额】k 很小时 3×k 会太小（branch=4 时只有 12 个），所以取 max(3k, 24)，
 * 让小分支的搜索完全不受影响。
 */
function aiOrderTop(board, cands, mover, foe, winLength, moverRes, foeRes, k, preFilter) {
  const n = cands.length / 3;
  const sc = [];
  if (!preFilter || n <= AI_ORDER_FLOOR) {
    for (let i = 0; i < cands.length; i += 3) {
      const x = cands[i], y = cands[i + 1], z = cands[i + 2];
      const v = aiOrderKey(board, x, y, z, mover, foe, winLength, moverRes, foeRes);
      sc.push({ x: x, y: y, z: z, v: v, mine: AI_ORDER.mine, d: aiCenterDist(board, x, y, z) });
    }
    sc.sort(aiSearchCompare);
    return sc;
  }
  const keep = Math.max(3 * k, AI_ORDER_FLOOR);
  const cheap = [];
  for (let i = 0; i < cands.length; i += 3) {
    const x = cands[i], y = cands[i + 1], z = cands[i + 2];
    cheap.push({ x: x, y: y, z: z, c: aiCheapKey(board, x, y, z) });
  }
  // 全序：廉价键降序 → 坐标升序。同分也确定，否则同一种子在不同引擎上会排出不同顺序。
  cheap.sort((a, b) => (b.c - a.c) || (a.x - b.x) || (a.y - b.y) || (a.z - b.z));
  const m = keep < cheap.length ? keep : cheap.length;
  for (let i = 0; i < m; i++) {
    const x = cheap[i].x, y = cheap[i].y, z = cheap[i].z;
    const v = aiOrderKey(board, x, y, z, mover, foe, winLength, moverRes, foeRes);
    sc.push({ x: x, y: y, z: z, v: v, mine: AI_ORDER.mine, d: aiCenterDist(board, x, y, z) });
  }
  sc.sort(aiSearchCompare);
  return sc;
}
```

```js
      if (o && o.status === MoveStatus.Win) foeWins.push(after[i], after[i + 1], after[i + 2]);

    if (foeWins.length > 0) { s.board.set(firstMove.x, firstMove.y, firstMove.z, EMPTY); return false; }
    // 我下一步的成五点 = 他必须堵的点

      if (o && o.status === MoveStatus.Win) blocks.push(after[i], after[i + 1], after[i + 2]);

    if (blocks.length / 3 >= 2) { s.board.set(firstMove.x, firstMove.y, firstMove.z, EMPTY); return true; }
```

```js
/* --------------------------------------------------------------------------
   算杀扩展：VCT（连续活三取胜）。

   【和 aiVcf 的关系】aiVcf 只走冲四（对方应手唯一，所以每个节点只有一个分支）；

   判为**未知（不算胜）**。宁可不报胜着，也**绝不许报假胜着** —— 后者会让电脑
   主动走出一手送死棋，而前者只是少赢一手。所以递归回来一次 null 就整个放弃。

   【预算】和 aiVcf 共用 aiVcfLeft（单位是"扫过多少个候选点"）。按点记账而不是
   按节点，见 aiVcf 里那段：50³ 密集局面下一格比 15³ 中盘贵三十倍。
   -------------------------------------------------------------------------- */

/** 每个 VCT 节点最多试几个活三着法。 */
const AI_VCT_M = 6;
/** 每个活三着法最多穷举几个对方应手。**超过这个数就必须判未知，不许猜。** */
const AI_VCT_D = 4;
/** VCT 的深度上限。比 VCF 浅 —— 活三的分支比冲四大得多。 */
const AI_VCT_DEPTH = 8;

/**
 * 找出 attacker 在这个盘面上能做的三类着法：
 *   wins   直接成五
 *   fours  冲四（对方应手唯一）
 *   threes 活三（对方应手多个）
 * 复用传入的 out，避免每个节点分配。
 */
function aiVctThreats(session, attacker, out, cands) {
  const board = session.board, rules = session.rules, fp = session.firstPlayer;
  const wl = rules.winLength;
  const res = rules.isRestricted(attacker, fp);
  out.wins.length = 0; out.fours.length = 0; out.threes.length = 0;
  for (let i = 0; i < cands.length; i += 3) {
    const x = cands[i], y = cands[i + 1], z = cands[i + 2];
    const t = aiThreatAt(board, x, y, z, attacker, wl, res);
    if (t.over > 0) continue;                 // 自尽点，算杀里绝不能走
    if (t.wins > 0) out.wins.push(x, y, z);
    else if (t.fours > 0) out.fours.push(x, y, z);
    else if (t.threes > 0) out.threes.push(x, y, z);
  }
  return out;
}

/**
 * 穷举对方的应手，写进 out（扁平三元组），返回个数。超过 cap 就返回 -1 表示"截断了"。
 *
 * 【为什么要穷举而不是取"最好的那个"】取最好的那个不构成证明：
 * 只要有一个应手能破，这个胜着就是假的。截断时返回 -1，调用方必须当作"未知"。
 */
function aiVctFoes(session, cands, foe, cap, out) {
  out.length = 0;
  for (let i = 0; i < cands.length; i += 3) {
    const x = cands[i], y = cands[i + 1], z = cands[i + 2];
    // 对方的应手包括：他自己能成五的点、以及他必须堵的点。
    // 两者都用同一条判据取 —— "这个点落下去对双方各自意味着什么"。
    const mine = aiOutcomeAt(session, x, y, z, foe, null);
    if (mine && mine.status === MoveStatus.Win) {
      // 他直接赢：这个局面不是我的胜着
      out.length = 0;
      out.push(x, y, z);
      return -2;                              // -2 = 对方有直接的胜
    }
    if (mine && mine.status === MoveStatus.LoseByOverline) continue;
    out.push(x, y, z);
    if (out.length / 3 > cap) return -1;      // 截断
  }
  return out.length / 3;
}

/**
 * VCT 主循环。找到必胜就返回第一步的坐标，否则 null。
 *
 * **返回 null 的含义是"没找到"，不是"没有"。** 截断、预算用尽、深度用尽都返回 null。
 * 这一点是刻意的：宁可少报，不可错报。
 */
function aiVct(session, attacker, depth, stats) {
  if (depth <= 0) return null;
  const board = session.board, rules = session.rules;
  const foe = opponentOf(attacker);
  const wl = rules.winLength;

  const cands = aiCandidates(board, AI_CANDIDATE_CAP);
  const cost = cands.length * 2;
  if (aiVcfLeft < cost) return null;
  aiVcfLeft -= cost;

  const mine = aiVctThreats(session, attacker, AI_VCT_A, cands);
  if (mine.wins.length > 0) return { x: mine.wins[0], y: mine.wins[1], z: mine.wins[2], win: true };
  if (mine.fours.length === 0 && mine.threes.length === 0) return null;

  // 对方自己能成五 → 我冲我的，他直接赢，整条链作废（和 aiVcf 同一条）
  if (aiVcfFoeWins(session, cands, foe) >= 1) return null;

  // ---- 第一类：冲四。对方应手唯一，走原样的逻辑（最便宜、最可靠）
  for (let i = 0; i < mine.fours.length; i += 3) {
    const x = mine.fours[i], y = mine.fours[i + 1], z = mine.fours[i + 2];
    board.set(x, y, z, attacker);
    const afterCands = aiCandidates(board, AI_CANDIDATE_CAP);
    if (aiVcfLeft < afterCands.length) { board.set(x, y, z, EMPTY); return null; }
    aiVcfLeft -= afterCands.length;
    const after = aiVctThreats(session, attacker, AI_VCT_B, afterCands);
    if (after.wins.length >= 6) {            // 两个以上成五点：一手堵不住
      board.set(x, y, z, EMPTY);
      return { x: x, y: y, z: z, win: true };
    }
    if (after.wins.length === 3) {           // 恰好一个：他的应手唯一
      const bx = after.wins[0], by = after.wins[1], bz = after.wins[2];
      board.set(bx, by, bz, foe);
      const sub = aiVct(session, attacker, depth - 1, stats);
      board.set(bx, by, bz, EMPTY);
      if (sub) { board.set(x, y, z, EMPTY); return { x: x, y: y, z: z, win: true }; }
    }
    board.set(x, y, z, EMPTY);
  }

  // ---- 第二类：活三。**这一支才需要穷举应手，也是唯一可能造成假胜着的地方**
  const nM = mine.threes.length / 3;
  const lim = nM < AI_VCT_M ? nM : AI_VCT_M;
  if (lim < nM) return null;                 // 活三太多，截断了 → 判未知，不许猜
  for (let i = 0; i < mine.threes.length; i += 3) {
    const x = mine.threes[i], y = mine.threes[i + 1], z = mine.threes[i + 2];
    board.set(x, y, z, attacker);
    const afterCands = aiCandidates(board, AI_CANDIDATE_CAP);
    if (aiVcfLeft < afterCands.length) { board.set(x, y, z, EMPTY); return null; }
    aiVcfLeft -= afterCands.length;

    // 我这一手之后自己能不能直接成五
    const after = aiVctThreats(session, attacker, AI_VCT_B, afterCands);
    if (after.wins.length >= 6) {
      board.set(x, y, z, EMPTY);
      return { x: x, y: y, z: z, win: true };
    }
    if (after.wins.length === 3) {
      // 我有一个成五点：对方只能堵那里，退化成冲四那一支
      const bx = after.wins[0], by = after.wins[1], bz = after.wins[2];
      board.set(bx, by, bz, foe);
      const sub = aiVct(session, attacker, depth - 1, stats);
      board.set(bx, by, bz, EMPTY);
      if (sub) { board.set(x, y, z, EMPTY); return { x: x, y: y, z: z, win: true }; }
      board.set(x, y, z, EMPTY);
      continue;
    }

    // 【关键】穷举对方所有应手。任何一个防住 → 这一支不成立。
    const nFoe = aiVctFoes(session, afterCands, foe, AI_VCT_D, AI_VCT_FOES);
    if (nFoe === -1 || nFoe === -2) { board.set(x, y, z, EMPTY); return null; }
    let allLose = true;
    for (let f = 0; f < AI_VCT_FOES.length; f += 3) {
      const fx = AI_VCT_FOES[f], fy = AI_VCT_FOES[f + 1], fz = AI_VCT_FOES[f + 2];
      board.set(fx, fy, fz, foe);
      const sub = aiVct(session, attacker, depth - 1, stats);
      board.set(fx, fy, fz, EMPTY);
      if (!sub) { allLose = false; break; }  // 他防住了 → 这一支不成立
    }
    board.set(x, y, z, EMPTY);
    if (allLose) return { x: x, y: y, z: z, win: true };
  }
  return null;
}
```

```js
 * 对手有没有强制胜。**就是拿对方当 attacker 再跑一遍算杀。**
 *
 * 【为什么复用 aiVct 而不是另写一个"防守搜索"】攻守是同一件事：
 * "他执子时能不能强杀" 和 "我执子时能不能强杀" 用的是同一段逻辑，
 * 只是 attacker 参数不同。另写一份 = 两份会漂移的判据，
 * 而这个工程已经因为"同一件事写两遍"踩过坑（颜色散在五处、worldOf 两份拷贝）。
 *
 * 【返回 false 的含义是"没找到"，不是"没有"】预算用尽、深度用尽、被截断，
 * 全都返回 false。所以这个过滤是**启发式**，不是证明 ——
 * 它只会让引擎少走坏棋，不会让它把好棋当成坏棋丢掉。
 *
 * 调用方必须自己重置 aiVcfLeft 预算（用 aiVcfBudgetReset），本函数不动它。
 */
function aiFoeCanWin(session, foe, depth, stats) {
  return aiVct(session, foe, depth, stats) !== null;
}
```

```js
                          session.rules.isRestricted(mover, session.firstPlayer),
                          session.rules.isRestricted(foe, session.firstPlayer), K, false);

    for (let i = 0; i < sc.length && i < K; i++) {
      const m = sc[i];
      board.set(m.x, m.y, m.z, mover);
      aiVcfBudgetReset();                       // 每个候选独立预算，不然前几个吃光后面的
      const loses = aiFoeCanWin(session, foe, AI_VCT_DEPTH, stats);

    if (alive.length > 0) {
      safe.length = 0;
      for (let i = 0; i < alive.length; i++) safe.push(alive[i]);
    }
```

```js
/**
 * 转动候选：3 轴 × n 层 × 3 个顺时次数，剔掉空层，按「层里子多」降序、
 * 同分按 axis/layer/turns 升序 —— **全序，同一种子在不同引擎上必须排出同样的顺序**。
 * limit <= 0 表示不截断（极限档全枚举）。
 */
function aiRotationCandidates(session, limit) {
  const board = session.board;
  const n = board.size;
  const list = [];
  for (let ai = 0; ai < 3; ai++) {
    const axis = AI_AXES[ai];
    for (let layer = 0; layer < n; layer++) {
      const stones = board.countLayerStones(axis, layer);
      if (stones === 0) continue;
      for (let turns = 1; turns <= 3; turns++) list.push([axis, layer, turns, stones]);
    }
  }
  list.sort((a, b) => (b[3] - a[3]) || (a[0] - b[0]) || (a[1] - b[1]) || (a[2] - b[2]));
  const lim = (limit > 0 && limit < list.length) ? limit : list.length;
  const out = [];
  for (let i = 0; i < lim; i++) out.push({ axis: list[i][0], layer: list[i][1], turns: list[i][2] });
  return out;
}
```

- [ ] **Step 5: 写 `aiRotationValue`**

```js
/**
 * 一次转动值多少 —— **用和落子完全相同的搜索引擎估值**，这是"同台竞价"的全部含义。
 *
 * 【为什么必须走 probeRotate 而不是自己转】转动判定只此一份（_tryRotate），
 * 挑了一手引擎会拒的动作会让电脑【卡住不动】。probeRotate 无论成不成都会还原、
 * 不记账、不占回合，而且求值夹在中间、还原走 finally。
 *
 * 【为什么重算整盘哈希而不是增量】转动是整层置换，增量要逐格异或 n² 次；
 * 全量重算也是 O(cellCount)，n² 相对 cellCount 不占优势，而全量重算不会写错。
 *
 * 失败（引擎拒了 / 没搜出东西）返回 -Infinity —— 调用方只在它更大时才采用。
 */
function aiRotationValue(session, params, rot, mover, stats) {
  const board = session.board;
  let value = -Infinity;
  const o = session.probeRotate(RotationMove.fromClockwiseTurns(rot.axis, rot.layer, rot.turns),
    () => {
      // 转完轮到对方走，所以估值的是"对方走之前"这个局面。
      // 用 aiSearchMove 的同一套：先算杀（防守方视角不适用，跳过），直接走搜索估值。
      const safe = [];
      const cands = aiCandidates(board, AI_CANDIDATE_CAP);
      for (let i = 0; i < cands.length; i += 3) {
        const m = aiOutcomeAt(session, cands[i], cands[i + 1], cands[i + 2], mover, stats);
        if (m && m.status === MoveStatus.LoseByOverline) continue;
        safe.push(cands[i], cands[i + 1], cands[i + 2]);
      }
      if (safe.length === 0) return;
      const r = aiSearchMove(session, safe, params, stats);
      if (r) value = r.v;
    });
  if (stats) stats.rotProbes++;
  return o.accepted ? value : -Infinity;
}
```

**注意**：`aiSearchMove` 内部用的是 `session.currentPlayer` 作为 mover，而探针期间会话的出子权**没有变**（转动不占回合），所以它算的是"转完之后轮到谁"。这一点要确认：`probeRotate` 不改 `currentPlayer`，而转动的语义是"转完该对方走"。所以 `aiSearchMove` 会拿 `currentPlayer === mover` 去估值，**方向反了**。

```js
  const board = session.board, rules = session.rules, winLength = rules.winLength;
  const mover = moverOverride || session.currentPlayer;
  const foe = opponentOf(mover);
```
